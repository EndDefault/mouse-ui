# docs 구조 안내

이 폴더는 `mouse-ui`의 제품 방향, 개발 흐름, 작업 규칙을 정리한다.

초기에는 버전마다 세세한 체크리스트를 따라갔지만, `v0.5.0` 이후부터는 기능 구현 속도와 실제 사용성 개선을 더 중요하게 둔다. 따라서 문서는 매 기능마다 고치는 대상이 아니라, 방향이 바뀌거나 큰 작업 묶음이 끝났을 때 정리하는 기준으로 사용한다.

## 먼저 볼 문서

- [작업 흐름 설명서](workflow.md): 앞으로 작업을 어떻게 진행할지 정리한 운영 기준
- [제품 기획서](product_plan.md): 이 프로젝트가 무엇을 만들고 있는지 설명하는 제품 기준
- [파일 구조 및 분리 규칙](file_structure_rules.md): 새 기능을 어느 폴더와 파일에 둘지 판단하는 기준

## 작업 규칙 문서

- [개발 방향 및 규칙](development_rules.md): 상태, 데이터, UI, 코드 생성의 기본 원칙
- [커밋 규칙](commit_convention.md): 기능 단위 커밋 메시지 기준
- [PR 작성 규칙](pr_convention.md): PR을 만들 때 제목과 본문을 쓰는 기준

## 버전과 기록 문서

- [버전 관리 및 체크리스트](version_checklist.md): `v0.5.0`까지의 진행 상태와 다음 큰 방향
- [변경 기록](change_log.md): 프로젝트 방향이나 기준이 바뀐 큰 결정을 기록

## 현재 문서 운영 방식

- 기능 하나를 만들 때마다 모든 문서를 갱신하지 않는다.
- 기능 커밋과 문서 커밋은 분리한다.
- 버전이나 큰 작업 묶음이 끝날 때 README와 docs 상태를 확인한다.
- 방향이 바뀌면 `workflow.md`, `version_checklist.md`, `change_log.md`를 우선 갱신한다.

## 현재 방향

`v0.5.0`까지의 작업은 현재 프로젝트의 첫 저장 가능한 기준점으로 본다.

다음 단계는 `v0.6.0`을 별도로 진행하기보다, `develop`과 `main`에 지금까지의 작업을 저장한 뒤 `v1.0.0`을 향해 구조와 사용성을 새 기준으로 재정의하는 것이다.
