# 버전 관리 및 체크리스트

이 문서는 Visual UI Code Builder를 버전 단위로 만들기 위한 기준이다.

큰 목표는 한 번에 완성하려고 하지 않고, 작은 버전마다 사용할 수 있는 기능을 하나씩 쌓는 것이다. 각 버전은 체크리스트를 기준으로 완료 여부를 판단한다.

## 1. 버전 관리 방식

버전은 `v0.1.0`부터 시작한다.

초기 개발 단계에서는 아래 기준을 사용한다.

- `v0.x.0`: 새로운 기능 묶음이 추가되는 버전
- `v0.x.1`: 같은 버전 안에서 작은 버그 수정이나 문서 수정
- `v1.0.0`: MVP 기능이 안정적으로 완성된 첫 정식 버전

예시는 다음과 같다.

```txt
v0.1.0  기본 UI 빌더 구조
v0.2.0  드래그 이동과 크기 조절
v0.3.0  속성 패널
v0.4.0  컴포넌트 종류 확장
v0.5.0  저장, 불러오기, 코드 복사
v1.0.0  1차 MVP 완성
```

## 2. 체크리스트 사용 규칙

- 새 기능을 만들기 전 현재 목표 버전을 확인한다.
- 구현할 항목은 `[ ]` 상태로 둔다.
- 기능을 구현하고 직접 확인한 뒤 `[x]`로 바꾼다.
- 체크리스트에 없는 큰 기능은 바로 만들지 않고 다음 버전에 넣을지 먼저 판단한다.
- 한 버전의 범위가 너무 커지면 다음 버전으로 나눈다.

## 4. 현재 전환 단계

`v0.5.0` 구현을 끝낸 뒤, 지금까지의 작업을 `develop`과 `main`에 저장하고 `v1.0.0` 새 기준으로 넘어가기 전에 아래 전환 절차를 거친다.

`v1.0.0` 구현은 아래 순서가 끝난 뒤 새 브랜치에서 시작한다.

- [ ] 현재 `feature/v0.5.0-storage-copy` 브랜치를 push한다.
- [ ] `develop`을 base로 `v0.5.0` PR을 만든다.
- [ ] PR 검토 후 merge한다.
- [ ] `main`을 base로 `develop` 반영 PR을 만든다.
- [ ] `main`에 지금까지의 작업을 저장한다.
- [ ] `v1.0.0` 작업 브랜치를 새로 만든다.
- [ ] 새 브랜치에서 구조와 사용성 기준을 다시 정의한다.

전환 단계에서는 아래 작업을 하지 않고, 새 브랜치에서 시작한 뒤 `v1.0.0` 작업에서 처리한다.

- 우클릭 메뉴
- 삭제와 복제
- UI 정리와 사용성 개선
- 컴포넌트 정의, Inspector, codegen 구조 정리
