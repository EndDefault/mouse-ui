# v1 작업 흐름

v1은 기능을 바로 붙이는 단계가 아니라, 기획과 데이터 기준을 먼저 맞춘 뒤 구현한다.

## 기본 흐름

1. 사용자가 목표와 우선순위를 정한다.
2. 필요한 데이터 구조를 먼저 정의한다.
3. 파일 위치와 책임 범위를 정한다.
4. 기능 단위로 구현한다.
5. 체크리스트로 동작을 확인한다.
6. 기능 커밋과 문서 커밋을 분리한다.
7. 큰 작업 묶음이 끝나면 PR을 만든다.

## 기능 하나를 만들 때

기능 하나는 아래 순서로 진행한다.

1. 기능의 사용자 흐름을 한 문장으로 정리한다.
2. 필요한 project/component 데이터 변경을 확인한다.
3. 변경할 파일 위치를 `file_structure.md` 기준으로 정한다.
4. UI와 상태 변경을 구현한다.
5. 캔버스 렌더링, Inspector, codegen, 저장/불러오기 영향을 확인한다.
6. `checklist.md`의 해당 항목을 확인한다.
7. 기능 단위로 커밋한다.

## 문서 업데이트 기준

- 기획이 바뀌면 `product_plan.md`를 수정한다.
- 구현 순서가 바뀌면 `checklist.md`를 수정한다.
- 데이터 형태가 바뀌면 `data_rules.md`를 수정한다.
- 파일 배치 기준이 바뀌면 `file_structure.md`를 수정한다.
- 단순 구현 중에는 모든 문서를 매번 고치지 않는다.

## Codex 작업 기준

- 사용자가 정하지 않은 다음 작업을 문서에서 확정하지 않는다.
- 구현 전에 필요한 데이터와 파일 위치를 먼저 확인한다.
- 기능은 가능한 작게 나누어 커밋한다.
- 문서 변경은 기능 구현 커밋과 분리한다.
- PR 본문에는 변경 내용, 변경 이유, 확인한 것, 관련 문서, 다음 작업을 적는다.

## PR 단위

PR은 하나의 목적을 가져야 한다.

좋은 PR 단위:

- 캔버스 이동 / 줌 기능
- 화면 크기 지정 기능
- 컨테이너와 내부 요소 추가 흐름
- 그라데이션 스타일 기능
- 애니메이션 데이터와 설정 UI
- v1 데이터 구조 정리

너무 큰 PR이 될 것 같으면 기능 구현과 문서 정리를 분리한다.
